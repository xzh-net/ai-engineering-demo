# 常见问题（使用者排障）

> 只收**使用过程中**会遇到的问题；修改者向的缺陷修复纪律不在本文件。
> 格式：现象 / 判断方法 / 处置。新问题按此格式追加，不写日期与修改史。

### 1. AI 声称"已更新/已验证"，但文件里查无此状态

- 现象：会话汇报说某状态已更新，翻文件却没找到（或反过来，把"必报项的更新区域清单"误读成了"已更新的结果"）。
- 判断方法：**证据链核对**——§1.2 看板 ↔ §1.3 状态列 ↔ §1.6 任务表（任务ID/证据路径）↔ 方案 §X 回写，外加 `docs/验证记录/` 有无当次档案；状态一律**以文件实际内容为准**。
- 处置：让 AI 补落盘（虚报则按 §8.1 记问题）；长期如此说明必报项执行在漏，回到 `流程与机制.md` 的五件套检查汇报格式。

### 2. AI 未经明确告知就抢跑执行任务

- 现象：你只说"考虑/准备"，AI 已经动手改文件、跑命令。
- 判断方法：任务性质是否到了"明确指令"级。
- 处置：当场叫停 + "**把这条写进 AGENTS**"（落成 §三流程约束："先答复、得到明确告知再开始"）。

### 3. 新会话答不出"项目到哪了"

- 现象：开新会话，AI 追问你项目背景。
- 判断方法：三问验收——到哪步 / 下一步 / 按哪个流程。
- 处置：对照 `流程与机制.md` 补齐（§1.2 指针行、§1.6 结构化任务表、§1.7 入口协议、§十必报段），并确认工作目录=项目根。

### 4. 终端输出中文乱码，疑似文件损坏

- 现象：命令回显里路径/中文全是问号或方块。
- 判断方法：**用文件读取接口核对**（读文件工具/编辑器），不要信终端回显。
- 处置：多为控制台编码问题，文件完好则不动；仅当读接口也显示异常才修文件。

### 5. 状态机内容无处落位 / 被写进了方案

- 现象：生成 AGENTS 后 §1.2 空洞，状态与阶段内容堆在技术选型文档里；或 AI 自行新建了一个"状态机文件"。
- 判断方法：**§1.2 四件套检查**（状态表 / 判定条件 / 切换清单 / 激活指针）+ 判定条件与方案行项 1:1 + 方案内无 ✅/⬜ 看板。
- 处置：按 `README.md` 的产物落点表回炉 P1 第 2 条（模板 §1.2 骨架 → 落 AGENTS §1.2 → 内容取方案 → 禁入方案）。

### 6. 生成的分册是通用骨架，验证标准看似要自己写

- 现象：P2 跑完打开分册，只有通用六步，没有本项目的验证项/标准/预案，误以为标准要手工填。
- 判断方法：分册有无"**本阶段验证项清单**"章节，且逐项能对回方案 §X 行。
- 处置：重跑 `prompts/P2_分册.md`（读方案阶段表 → 生成清单章节，标准值带出处）。

### 7. P0 产出缺"架构/自研边界"，P1 无依据可依

- 现象：P0 方案有候选对比和验证路线，但没有整体架构分层/模块划分，也没写自研聚焦——P1 生成 AGENTS §6.1 模块表与 §5.1 时无据可编，只能瞎编或抄模板。
- 判断方法：对照 `资产/模板_技术选型方案.md` **九节契约**逐节打勾，重点看第 3 节（架构与模块）与第 2 节（自研聚焦）。
- 处置：按模板重跑 P0，或手补该两节后再发 P1。

### 8. 新会话没先说"续接四问"，或四问答不齐

- 现象：新会话直接开始改文件；或"阶段与分册 / 任务与状态 / 挂起与拍板 / 一致性核对"有项答不出。
- 判断方法：AGENTS 有无 §1.7 入口协议；§1.6 任务表是否七字段齐、进行中任务有编号、已完成有证据、下一步非空。
- 处置：对照 `流程与机制.md` 的 §2.5 补齐 §1.7 与 §1.6；先让当前会话回填状态，再开新会话验收。

### 9. 验证报告写出来，一半是"待补测"或模糊判定

- 现象：P4 生成报告，证据表多行"待补测"，或出现"基本通过""大致达标"这类词。
- 判断方法：打开 `docs/验证记录/` 查每个 V-NN 有无原始数据（环境/样本量/实测值）；点数分册项数与证据表行数；判定是否只用四值。
- 处置：缺数据的项回 P3 补测并补记录；判定只准 `通过/不通过/待补测/不适用`；无原始数据不得写"通过"（见 [`资产/模板_选型验证报告.md`](资产/模板_选型验证报告.md) §1）。

### 10. 测试没达标，想把阈值调低让它"通过"

- 现象：实测值低于方案阈值，想改报告里的通过标准。
- 判断方法：阈值只能逐字取自方案 §X；报告中改阈值 = 改选型基线，不是改写法。
- 处置：交你拍板；同意后先回写方案 §X（并记录技术决策），再按新阈值重判；不同意则启用方案里的备选 A/B。
