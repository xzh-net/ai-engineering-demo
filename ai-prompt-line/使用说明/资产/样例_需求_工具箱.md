# 工具箱自动化管理工具

## 1. 目标

在 Windows 10/11 桌面环境，通过 Android 模拟器（多开）运行「工具箱」APP，构建一个桌面端自动化管理工具，覆盖 5 项能力：

| 能力 | 说明 |
| --- | --- |
| 多开实例管理 | 批量新建、克隆、启动、退出模拟器实例〔燃料：目标规模 10–20 个实例〕 |
| 设备通信 | 与每个实例建立 ADB 连接，执行 shell 命令、注入点击/滑动 |
| 界面识别 | 识别实例当前界面状态与关键控件〔燃料：5 类页面——登录/首页/分类/收藏/我的〕 |
| 任务调度 | 定时、多实例并行执行任务流；单实例故障只隔离该实例，不拖垮整体 |
| 桌面管理界面 | 实例面板、任务配置、运行日志三个视图 |

## 2. 边界与性质

- 项目性质：测试与学习项目；纯本地离线运行，不对外提供服务、不上传任何数据。
- 明确不做：不绕过登录/支付/风控，不触碰他人账号与数据，不引入真机云控/群控。
- 受控对象与授权范围：仅操作本人自建的模拟器实例与自持 APP；平台条款是否允许本用途，须在技术验证前取得书面确认〔燃料：合规前置项——需书面确认〕。

## 3. 其它约束

- 目标机器：Windows 10/11，16GB 内存〔燃料：16GB / Win10–11 单机〕。
- 使用者与场景：个人单机使用，无多人协作、无远程访问诉求。
- 运行时长：设计为可连续长时间运行〔燃料：可连续运行 72h 级〕。

## 4. 提案与假设清单

- 【需求待确认】实例规模上限：建议默认 20 个（多开工具常见上限，且与 16GB 内存匹配）｜理由：超出后单机内存与 ADB 连接数风险上升。
- 【需求待确认】平台条款书面确认的时点：建议默认放在技术验证之前的合规前置阶段｜理由：条款不允许则后续验证无意义。
- 假设：目标机器为本人自用 Windows 10/11、16GB 内存，已按默认填入 §3。
- 假设：仅操作本人自建模拟器与自持 APP，无多人协作与远程访问，已按默认填入 §2。
- 用户确认结果：待确认
