# AGENTS.md — demo-toolbox · 演示工具箱

## 一、项目基本信息

### 1.1 项目定位

**demo-toolbox** 是一个基于 Python 3.11 的本地命令行工具箱，覆盖 3 项能力：

| 能力 | 说明 |
|---|---|
| 冷启动 | 进程启动到可接受命令的耗时 |
| 内存占用 | 常驻进程峰值内存 |
| 多显示器适配 | 窗口位置在双屏下不越界 |

项目性质：测试与学习项目；本地离线运行，免费，无联网依赖。

开发模式：**持续迭代——边验证、边开发、边总结。**

- 技术方案以《技术选型方案》（`docs/技术选型/2026-10-22_技术选型方案.md`）为唯一基线。
- 开发中发现的问题与验证结论必须双写留痕。
- 优先保证模块独立与运行稳定。

## 二、项目文档管理规范

### 2.1 文档优先原则

开始任何任务前，按序读：方案基线 → 需求文档 → 验证记录 → 问题记录 → 当前激活分册。文档与实测不一致时，先查记录与决策，确认后再同步。

### 2.2 文档分类与根目录规则

| 文档类型 | 保存目录 |
|---|---|
| 需求文档 | docs/需求文档/ |
| 技术选型 | docs/技术选型/ |
| 验证记录 | docs/验证记录/ |
| 问题记录 | docs/问题记录/ |
| 学习记录 | docs/学习记录/ |
| 阶段工作流分册 | docs/工作流/ |

**项目根目录只保留**：`docs/`、`AGENTS.md`、`README.md`（`.git/`、`.gitignore` 除外）。

### 2.3 文档命名

`YYYY-MM-DD_文档名称.md`，日期用实际创建日期，不允许伪造。

### 2.4 验证结论回写规则

每个验证阶段结束后必须**双写**：

1. 完整过程 → `docs/验证记录/`（覆盖证据六要素）；
2. 结论 → 方案 §6 对应阶段处追加"验证结论"小节；
3. 全部验证项跑完后汇总为《选型验证报告》→ `docs/技术选型/2026-11-05_选型验证报告.md`。

## 三、持续开发工作流程

| 任务类型 | 特征 | 执行方式 |
|---|---|---|
| 验证任务 | 回答方案某验证项的通过/不通过，产出数据 | 按激活分册的验证六步 |
| 工程任务 | 配置、日志、文档等稳定部分 | 通用六步，受 §1.5 门禁约束 |

通用六步：理解任务 → 分析与规划 → 实施 → 功能验证 → 开发总结 → 向用户汇报。

## 十、每次任务的最终交付规范

1. 本次任务
2. 修改文件
3. 实现内容
4. 验证结果（已通过 / 未通过 / 尚未验证）
5. 状态同步：§1.2 看板、§1.3 状态列、§1.6 任务表与四查
6. 开发记录 / 验证记录位置
7. 遗留问题
8. 下一步建议

不允许虚报测试结果或省略重要异常。

## 十一、最高优先级原则

1. 用户明确需求优先于 AI 推测。
2. 已确认技术选型优先于 AI 推荐；已否决方案不得擅自翻案。
3. 已有代码与历史记录优先于重新设计。
4. 实际验证结果优先于理论推测。
5. 未经验证的功能不能声称完成。
6. 重要技术变更必须记录并回写方案。
