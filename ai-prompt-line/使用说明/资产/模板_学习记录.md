## 1. 双记忆与回路规则【必填 · 结构必留】

- **规则记忆** = 项目 `AGENTS.md`（长期约束，跨会话注入）；**案例记忆** = 本文件（事实、证据、候选与去向）。
- **候选 ≠ 规则**：先有事实与证据，才有候选条文；候选经用户确认后才写入规则。
- **根因单层**：每条候选只归一层（提示词 / 模板 / 质检 / 使用说明 / AGENTS / 执行），跨层连改是事故之源。
- **条文可执行**：祈使句、可直接粘贴；禁日期、禁实例名、禁硬编码章节号（泛化三不）。
- **工具环只记录**：跨项目复用的模板/提示词/质检缺陷，只在本文件记候选，**不得自动改写工具仓**；由用户人工回灌。
- **未验证不算学会**：规则生效后须在下一次同类任务、新会话或送检中验证；未验证前不得写"已学习"。

## 3. 规则候选表【必填 · 每条候选一行】

| 候选ID | 现象 | 根因层 | 建议条文 | 环（项目/工具） | 拟生效位置 | 影响引用 | 状态 | 拍板人 | 日期 |
|---|---|---|---|---|---|---|---|---|---|
| {L-01} | {同一现象/同一错误} | {提示词/模板/质检/使用说明/AGENTS/执行} | {可直接粘贴的祈使句} | {项目} | {AGENTS §X.X} | {被同步的文件} | {候选} | {用户} | {YYYY-MM-DD} |

- **编号唯一**：候选 ID 按**项目全局连续递增**；建新记录前先查历史学习记录的最大 L 编号——`L-NN` 不复用、不跨文件重号（含已否决条目）。
- **状态四值**：`候选` / `已确认` / `已生效` / `已否决`；只有用户能把 `候选` 改为 `已确认`。
- **项目环**：用户确认后写入 `AGENTS.md` 对应章节（或分册），并在 §1.8 留痕。
- **工具环**：候选停在 `已确认`，由用户带回工具仓回灌；本文件不指导自动改写。
- **升级规则**：同一现象第三次出现，必须产出一条工具环候选（不再是项目内打补丁）。

## 生成后自查（P5 收尾必做 · 实测不看自称）

- [ ] 每条候选都能在 §2 找到对应证据路径
- [ ] 每条候选只定一个根因层，没有"既改提示词又改模板"
- [ ] 建议条文无日期、无实例名、无硬编码章节号
- [ ] 工具环候选零直接改写（`git status` 里没有工具仓文件变动）
- [ ] 候选状态与生效动作一致（未确认的不在 AGENTS 里）
- [ ] 已否决清单里的条文没有被重复提议（无新证据），且 §6 写有本次复核结论
- [ ] 候选ID 全局递增、无跨文件重号
- [ ] 确认回写后已更新：§5 有验证方式与"未验证"、文件头状态改"已归档"、本自查逐项重跑
