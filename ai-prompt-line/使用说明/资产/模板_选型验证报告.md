> 使用说明（在工具仓，项目内无此文件）：使用说明/操作说明.md（S7）与 使用说明/流程与机制.md（§2.6）
> 配套：同目录 [`模板_技术选型方案.md`](模板_技术选型方案.md)（阈值出处 §X）、[`模板_验证阶段工作流.md`](模板_验证阶段工作流.md)（验证项编号 V-NN）、[`模板_AGENTS项目规范.md`](模板_AGENTS项目规范.md)（§1.6 证据字段）
> **用法**：使用说明/操作说明.md 的 **S7【P4】段**要求"按本模板生成"。本模板是"结论可证"的契约：**没有证据的结论一律不算数**。

## 文件头（元信息）【必填】

```markdown
- 日期：{YYYY-MM-DD}
- 依据：《{方案文档名}》`{方案路径}`；`{AGENTS.md 路径}`
- 覆盖范围：{阶段 0–2 全部验证项 V-01 ~ V-NN / 全部}
- 状态：**草案 → 待验收 → 已验收**（当前态加粗；已验收 = 用户确认）
```

> 状态是唯一凭据：`已验收` 之前，报告里的结论**不得**被当作选型基线引用。

## 1. 判定规则【必填 · 结构必留】

先读本节，再看证据表；规则冲突时以本节为准。

- **判定只用四个值**：`通过` / `不通过` / `待补测` / `不适用`。禁止"基本通过""大致达标""建议优化"等模糊词。
- **无原始数据 = 未验证**：缺"原始数据路径"或"实测值"的项，判定最多为 `待补测`，**不得**写 `通过`。
- **阈值只读**：阈值（含样本量/测量方法）逐字取自方案 §X 对应行，报告不得改阈值；确需调整 = 选型基线变更，经用户拍板后先回写方案，再重判。
- **按阈值比较**：实测值 vs 阈值，必须写明统计口径（最大值 / 平均 / 成功率 / 分位数）；样本量不足 = `待补测`。
- **环境可复现**：平台 / 版本 / 设备 / 关键配置写全；无法复现的环境，在判定后加"（环境不可复现）"。
- **`不适用` 受限定**：仅限方案明确标注可裁剪的项，必须写理由与方案出处行；不得用"不适用"掩盖未测。
  `不适用` 项的证据列（环境 / 样本量口径 / 原始数据路径 / 实测值 / 日期）统一填 `—`，不受"无原始数据 = 未验证"约束；理由与依据行写入 §3，涉及事实认定（如"项目非商用"）的必须写"拍板人：用户"。
- **不通过有出口**：必须指向方案 §X 的备选 A/B 与拍板人；未拍板的一项进 AGENTS §1.6 挂起表。

## 2. 证据表【必填 · 每项一行】

证据表行数必须等于分册"本阶段验证项清单"的项数，编号逐字一致（`V-NN`），不多不少。

| 编号 | 验证项 | 阈值（方案出处） | 环境 | 样本量/统计口径 | 原始数据路径 | 实测值 | 判定 | 日期 |
|---|---|---|---|---|---|---|---|---|
| {V-01} | {…} | {指标 阈值}（方案 §X 第 N 行） | {平台/版本/设备/配置} | {N 次，取最大值} | {docs/验证记录/…} | {实测值 + 单位} | {通过} | {YYYY-MM-DD} |

> 无证据的项照常占一行：原始数据路径写"无"，判定写"待补测"——**空行或删项视为漏项**。
> 唯一例外：`不适用` 项按 §1 规则填 `—`，理由与拍板人写进 §3。

## 3. 逐项说明【有则填 · 非"通过"项必填】

对每个 `不通过` / `待补测` / `不适用` 项给出：

- 归因：{环境问题 / 实施问题 / 阈值不可达 / 证据缺失}
- 下一步：{补测动作 / 启用备选 A 或 B / 提请拍板}；关联任务ID：{V-NN}
- 拍板人：{用户 / 无（可自决）}；`不适用` 涉及事实认定的，必须写"用户"。

## 4. 总体结论【必填】

- **计数**：通过 {N} / 不通过 {M} / 待补测 {K} / 不适用 {J}，合计 {总数}（与证据表行数、分册项数三方一致）。
- **结论三选一**：
  - `可交付`：全部为通过或不适用（不适用均有依据）；
  - `走备选`：存在不通过项，且备选已拍板；
  - `未收口`：存在待补测或未拍板项。
- **一句话依据 + 下一动作**：{进正式开发 / 验证备选 / 补测哪几项}。

## 5. 回写与一致性【必填 · 收口动作】

- 方案 §X：每阶段表下追加"验证结论：{计数}（报告：`{报告路径}`）"。
- AGENTS §1.6：相关任务的状态 / 证据记录 / 更新日期逐项更新。
- AGENTS §1.2：核对判定条件——全满足则宣告并执行切换清单；未满足写明尚缺哪几条。
- 报告状态改 `已验收` 需用户确认；未验收前不得作为基线。
