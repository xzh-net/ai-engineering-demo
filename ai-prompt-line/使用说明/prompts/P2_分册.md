# P2 · 目录与验证分册提示词（复制即用）

> 对应模板：`../资产/模板_验证阶段工作流.md`
> 用法：紧接 P1，在**目标项目根**同一会话续发；替换 `{花括号}`。
> 验收：分册名与 AGENTS §1.2 指针逐字一致、验证项清单七列齐全（含编号）、逐项能对回方案 §X。

```text
当前工作目录就是新项目根。输入：
- 分册模板：{模板_验证阶段工作流.md 的内容}
- 基线：{已生成的 AGENTS.md 路径（取 §1.2 分册命名与指针）+ 技术选型方案路径}
按 AGENTS §2.2 创建 docs/ 八类目录（需求文档/技术选型/架构设计/开发记录/验证记录/问题记录/技术决策/工作流）；
把分册模板生成为 docs/工作流/{分册名}.md——单期验证=验证阶段工作流.md，多阶段按 AGENTS §1.2
切换清单命名为 阶段N_阶段名工作流.md；替换方案文档名与阶段范围，【结构必留】章节不得删；
并读方案 §X 全部"分阶段验证路线"表，生成分册的"本阶段验证项清单"章节——按阶段分组，逐项给出：
编号（V-NN）｜验证项｜量化标准值｜出处（方案 §X 第 N 行）｜不通过预案｜本阶段产出物｜执行提示
（编号按阶段连续 V-01、V-02…，与 AGENTS §1.6 任务状态表的任务ID逐字一致；本项目上下文：脚本放 poc 哪个目录、样本量等）
标准值可入清单但必须标出处；
结论仍按 AGENTS §2.4 回写方案，清单不自行修改状态（状态只在 §1.2）；
生成 .gitignore（过滤 venv/__pycache__/缓存/日志/运行数据/打包产物/IDE，保留锁文件）；
完成后跑 git status 检查待提交清单并汇报。
```
