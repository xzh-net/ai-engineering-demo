# R · 需求文档提示词（复制即用）

> 对应模板：`../资产/模板_需求.md` ｜ 写法参照：`../资产/样例_需求_工具箱.md`
> 用法：把下方整段复制到 AI 会话，替换 `{花括号}`。任意会话可执行，可与 P0 同会话续。
> 验收：四节齐、能力表可验收、燃料事实带〔燃料：…〕、占位零残留。

```text
当前工作目录就是新项目根。输入：
- 需求模板：{模板_需求.md 的内容}
- 我的想法：{零散想法/背景/一句话目标——越乱越好，就是要你来整理}
  （示例：想做个图书馆管理系统，本地自己用，管图书、读者、借还书就行，最好能出报表——用 Java 和 SQLite 搞，别搞太复杂）
按模板结构产出**本项目真实需求文档**（1 目标【含能力表】/ 2 边界与性质 / 3 其它约束 / 4 提案与假设清单）：
1. 能力表：从我的想法提炼 3–6 项，**一行一能力、可验收**；你觉得缺了的补上并在提案清单标注；
2. 燃料事实必须显式化：影响后续验证阈值的具体数字与事实——目标规模（几实例/几类页面）、
   目标机器配置、运行时长/频率约束——写不出的标【需求待确认】；
   燃料事实在正文用〔燃料：…〕标注（与样例同形态，可 grep 复核）；
   （需求里每多一个事实，下一步方案里就少一条【阈值待拍板】）
3. 提案纪律（禁止开放式提问）：只有我能定的事实（规模、机器、使用者、授权范围、不做的边界），
   写入模板第 4 节《提案与假设清单》：逐项给出建议默认值 + 理由 +【需求待确认】标记，等我确认；
   常识可推导的直接填默认并列入假设清单，不提问；
4. 只写"要什么"，不写"用什么技术"（技术选型是下一步 P0 的事）；
   输入里已含的技术选型一概不进正文，要留痕就写进第 4 节假设。
保存为 docs/需求文档/{YYYY-MM-DD}_{项目名}需求.md（目录不存在先创建）；生成后自查：四节齐（第 1 节含能力表）？能力表可验收？
燃料事实都带〔燃料：…〕标注了？grep `{花括号}|待填|TODO` 占位零残留（**实测，不看自称**）？
事实类缺口是否全部进提案清单？——逐项报告，等我确认后再定稿。
```
