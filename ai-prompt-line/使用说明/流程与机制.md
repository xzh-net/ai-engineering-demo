## §一 AGENTS 是什么

**一句话定义**：放在项目根、被 AI 会话**自动加载**的规范文件——它是 AI 的**长期记忆替身 + 行为契约 + 项目状态看板**。

**决定后面一切机制的三个物理事实**：

1. 它是**静态文本**，永远不会自我修改；
2. 只要会话的**工作目录 = 项目根**，它就全文注入 AI 上下文（唯一硬前提）；
3. **AI 没有跨会话记忆**——今天没写进 AGENTS 的事，下个会话等于从未发生。

**它不是什么**：

- 不是 README（给人看的只是一句话定位）；
- 不是文档仓库（过程细节放 `docs/`，AGENTS 只放规则和指针）；
- 不是自动的（"更新"只能是任务里的显式动作，靠规则强制，见 §二五件套）。

**它解决什么**：① 换会话不丢上下文；② AI 行为不随聊天漂移；③ 项目状态永远有唯一真源。

## §二 AGENTS 机制是怎么样

### 2.1 总循环（一张图）

```text
你纠偏/拍板 ──→ 当场回写 AGENTS 成规则 ──→ 下次会话 AI 自动遵守
     ↑                                            │
     │                                            ▼
     │              汇报"状态同步"必报项 ──→ 四处状态文件始终贴近真实
     │                                            │
     └──── 新会话自动加载 AGENTS ←── 以项目根为工作目录开新会话
                    │
                    ▼
        按 §1.7 输出续接四问 → 你确认 → 看 §1.6"下一步"干活
```

### 2.2 五件套

| # | 件套 | 解决什么 | 关键条文（在生成项目的 AGENTS 里看） |
|---|---|---|---|
| 1 | **自动加载** | AI 记忆入口 | 工作目录=项目根（物理前提） |
| 2 | **阶段状态机 + 结构化状态** | 进度、切换、续接有唯一真源 | AGENTS **§1.2**（状态表 + 判定条件 + 切换清单 + 分册指针）+ **§1.6**（任务状态表七字段 + 完整性四查） |
| 3 | **选型状态门禁** | 未验证的技术不许盖楼（防返工） | AGENTS **§1.5**（状态列非"已验证"只准写 `poc/`，自带失效条款） |
| 4 | **双写沉淀** | 验证结论既留过程又留结论，不会丢 | AGENTS **§2.4** + 分册第五步（记录存 `docs/`、结论回写方案、阶段收口汇总为验证报告） |
| 5 | **汇报必报项** | **解决"AGENTS 不会自动更新"**：把更新变成每次汇报的必答动作 | AGENTS **§十"状态同步"**（四项更新 + §1.6 完整性四查 + 判定条件核对） |

### 2.3 两个常见疑问的标准答案

**问：新会话怎么"感知到"之前的进展？**
答：V0.2 起按 §1.7 强制入口协议：先读 §1.2 / §1.6 / 激活分册 / 方案，输出**续接四问**——① 阶段与分册 ② 任务与状态 ③ 挂起与拍板 ④ 一致性核对；你确认后再开工。细节（当时的数据、日志）去 `docs/验证记录/` 等目录读。

**问：AGENTS 会自己更新吗？**
答：**不会**。没有系统级自动机制。你看到的"更新" = 必报项强制某个会话的 AI 在收尾汇报时**显式改文件**。"自动"是（自动加载 × 必报强制 × 任务闭环）每圈转出来的**涌现效果**，动手的永远是"那个会话的 AI 按规则干的"。

### 2.4 人机分工

**AI 管干活和保鲜，你管拍板和纠偏；文件永远不用你动手，方向永远不交给 AI 自作主张。**

| 谁 | 干什么 |
|---|---|
| AI 自走 | 每任务状态更新、双写、续接、执行切换清单的机械步骤、主动提示规范缺口（**提议不擅改**） |
| 必须你拍板 | 不通过预案二选一、挂起事项、架构/核心依赖/选型变更、需求与合规、git commit/删除 |
| 你盯最后一道防线 | 三个失效信号：汇报长期"无需同步"／§1.6 落后一个任务／方案"待验证"悬空超一个阶段——出现即让 AI 补；§1.7 四问缺失或编造也算失效 |

### 2.5 V0.2 结构化状态与入口协议

- **结构化状态（§1.6）**：任务状态表七字段（任务ID / 类型 / 目标 / 状态 / 验收判据 / 证据记录 / 更新日期）+ 挂起待拍板表 + 下一步 + 完整性四查；状态枚举固定五个（待开始 / 进行中 / 挂起 / 已完成 / 已放弃）。
- **入口协议（§1.7）**：新会话先输出"续接四问"（阶段与分册 / 任务与状态 / 挂起与拍板 / 一致性核对），未输出不得开工；四处状态不一致时**只报告不擅改**。
- **编号贯通**：分册验证项 `V-NN` = §1.6 任务ID；证据路径、下一步、方案行项都按编号追溯，"可续"不靠散文复述。

### 2.6 V0.3 证据与验证报告

- **证据六要素**（每个验证任务）：环境（平台/版本/设备/配置）、样本量/统计口径、原始数据路径、实测值、阈值（带方案出处）、判定。
- **判定四值**：`通过` / `不通过` / `待补测` / `不适用`；**无原始数据 = 未验证**，最多判"待补测"；阈值只读，改阈值 = 方案变更须拍板。
- **报告唯一落点**：`docs/技术选型/{YYYY-MM-DD}_选型验证报告.md`，由 P4 生成、你验收；证据表行数 = 分册验证项总数。
- **方案 §7 只追加结论与报告路径**，不承载证据表；AGENTS §1.6 同步相应任务状态与证据。

### 3.2 五个必备件的最小骨架（缺一个机制就漏气）

```markdown

**当前阶段：{验证阶段} ｜ 激活分册：`docs/工作流/{分册名}.md`**
（单期验证=验证阶段工作流.md；多阶段=阶段N_阶段名工作流.md）
| 项 | 当前状态 |
|---|---|
| 项目阶段 | **{验证阶段}**（方案 §X 阶段范围） |

**切换动作清单**：1 新建分册并改指针 2 归档旧分册 3 更新状态表 4 回写方案/决策

<!-- ② §1.5 选型状态门禁（自带失效条款） -->

- 稳定部分（骨架/配置/日志/文档）不受限；
- 状态列全部"已验证"后本条自动失效。

<!-- ③ §1.6 结构化任务表（每任务收尾更新） -->
表头七字段（任务ID/类型/目标/状态/验收判据/证据记录/更新日期）+ 挂起表（事项/阻塞ID/拍板人/建议默认/日期）
+ 下一步（任务ID/动作/前置条件）+ 完整性四查；状态枚举：待开始/进行中/挂起/已完成/已放弃

<!-- ④ §1.7 新会话入口协议（强制门） -->
未输出"续接四问"（阶段与分册 / 任务与状态 / 挂起与拍板 / 一致性核对）不得开工；
缺信息写明缺哪项，不得编造、不得跳过。

<!-- ⑤ §十 状态同步必报段（原文格式） -->
状态同步：逐项回答（四项）：§1.2 看板、§1.3 状态列、§1.6 任务表（四字段 + 完整性四查）、方案 §X。
有更新列结果，无更新写"无需同步"。同时核对 §1.2 判定条件：全满足则宣告并执行切换清单；未满足写明尚缺哪几条。
```

## §四 使用指导

### 4.1 解决"后续会话自我感知"——AGENTS 里应该怎样写

原理一句话：AI 的"感知上个会话"= **读文件**，所以必须把"接头暗号"写在**固定位置**，让每个新会话一进来就知道去哪看。

**三个必写点：**

**例 A —— §1.2 头部指针行（状态机开门第一行）**

> 原文形态：`**当前阶段：验证阶段** ｜ 激活分册：docs/工作流/验证阶段工作流.md`

作用：新会话读一行就拿到"现在在哪 + 按哪套手册干活"两个关键信息。
反例：只写"项目介绍"不写这行 → AI 知道项目是什么，但不知道干到哪，只能追问你。

**例 B —— §1.6 结构化任务表 + §1.7 入口协议（写给 AI 自己看的操作说明）**

> 原文形态：§1.6 七字段任务表 + 挂起表 + 下一步 + 完整性四查；§1.7 "未输出续接四问不得开工"；四处状态不一致只报告不擅改。

作用：状态可机检、新会话不靠散文复述；反例：只有"进行中 / 下一步"两行散文，AI 会漏项或编造状态。

**例 C —— §十"状态同步"必报段（让感知材料永远新鲜）**

> 原文形态：`状态同步：逐项回答（四项）：§1.2 看板、§1.3 状态列、§1.6 任务表（任务ID/状态/证据/下一步四字段 + 完整性四查）、方案 §X。…同时核对 §1.2「判定条件」：全满足则宣告并执行切换清单；未满足写明尚缺哪几条。`

作用：没有这段，例 A/B 读到的三天后就是过期数据。**自我感知 = 读得见（A/B）+ 保鲜得了（C）**。

**验收方法（拿新会话实测）**：开一个全新会话只问一句——"这个项目现在到哪一步、下一步干什么、按哪个流程？"答对 = 机制成立；答"我不知道/请补充" = 三个必写点缺了哪个，回 §3.2 补。

### 4.2 解决"方案从验证 → 落地 → 指导正式开发"——验证状态机

**问题链**：设计方案写出来只是**假设** → 必须逐个技术点**真机论证**（带量化标准）→ 论证要**可控推进**（不带病进下一阶段）→ 全部论证完要**平滑切换到正式开发**。这条链需要一个"进度条 + 道岔"——这就是**验证状态机**。

**先纠正形态认知**：状态机**不是独立文件**，它是 AGENTS **§1.2 章节**；它是**索引式**的——只装四样东西（状态表 / 判定条件 / 切换清单 / 分册指针），**不装内容**（内容在方案、记录、分册里，靠指针引用）。

**如何使用（四步循环，每个阶段转一圈）**：

```text
① 开工：读 §1.2 → 当前阶段 + 激活分册
② 执行：按分册"验证六步"做真机验证 → 拿量化数据（不达标先归因再启用预案）
③ 收尾：必报回写 → §1.2 打勾/§1.3 状态列/§1.6 任务表（按任务ID） + 验证记录存档 + 方案 §X 结论回写
④ 收口：全部验证项跑完后按 P4 生成《选型验证报告》→ 你验收（状态改"已验收"）
⑤ 关口：核对判定条件 → 未满足：进下一验证项；全满足：当场执行切换清单
        （1 建开发分册改指针 2 归档验证分册 3 状态表改"正式开发阶段" 4 回写方案/决策）
```

**模板**：§1.2 最小骨架见 §3.2 ①；分册模板见 [`资产/模板_验证阶段工作流.md`](资产/模板_验证阶段工作流.md)——近零改动可复用。

**切换后 AGENTS 什么形态**（提前知道终点）：

- **脚手架烧尽**：门禁按自毁条款失效、判定条件/切换清单一次性执行成历史、验证回写规则触发改为"新选型才回"——约瘦 1/4–1/3；
- **契约永驻**：§1.6 结构化任务表、§1.7 入口协议、必报项、代码/汇报/优先级、**否决清单**（确定后更要防 AI"好心优化"翻案）原样保留；
- **机制可重挂载**：将来换选型，把 §1.3 状态列改回"待验证"，门禁与验证分册重新生效——它休眠，不销毁。

### 4.3 任务标准开合（速查卡）

| 时机 | 动作 |
|---|---|
| 开工 | §1.7 续接四问 → §1.6"下一步" → §三分诊（验证任务？工程任务？）→ 激活分册路径 |
| 收尾八段 | 本次任务 / 修改文件 / 实现内容 / 验证结果（四级状态）/ **状态同步（必报）** / 记录位置 / 遗留问题 / 下一步 |
| 阶段收口 | 全部验证项完成 → P4 报告（证据表逐项对 V-NN）→ 你验收"已验收" → 回写方案 §X / §1.6 / §1.2 判定条件 |
