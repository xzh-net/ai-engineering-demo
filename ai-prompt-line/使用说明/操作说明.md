# 操作说明 · 从 0 到 1 生成并验证一个新项目

> **八段提示词 + 分步操作全在本文件。** 每步四件事：做什么 → 复制哪段发会话 → 产出什么 → 怎么验收。
> 全部 AI 会话都以**目标项目根**为工作目录（AGENTS 自动加载的唯一硬前提）。
> 本文件属工具仓，对使用者**只读**：发现问题按 [`README.md`](README.md) 的送检流程反馈，不要就地改。

---

## 0. 复制与冻结原则（先读）

- **必须复制进目标项目**：6 份模板 + 质检清单 + 门禁检查器 → 项目内 **`docs/模板/`**（S0 一次完成）。复制件 = 该项目的**唯一输入源**，**只读、随项目冻结**；工具仓后续调整**不会**同步到已建项目（无升级动作）。
- **不复制**：本文件的八段提示词（用时复制到**会话**，不是项目）。
- **要改输入**（模板 / 质检判据 / 检查器）→ 回**工具仓**改，改完只影响新项目；在目标项目里改 `docs/模板/` = 制造双源，**禁止**。
- 目标项目 = 你自选的任意文件夹，与工具仓所在位置无关。

---

## S0 · 建项与复制（一次性）

1. 自选目标文件夹，在其中开后续所有会话（工作目录 = 该根）。
2. 建项与目录（Windows PowerShell，其余生成类目录可留到 S5 由 P2 建齐）：

```powershell
git init
New-Item -ItemType Directory -Force docs\模板, docs\需求文档, docs\技术选型, docs\工作流, docs\验证记录\原始数据, docs\问题记录, docs\学习记录, docs\开发记录, docs\技术决策, docs\架构设计
if (!(Test-Path README.md)) { Set-Content README.md "# 项目名" }   # 根规则要求 README 存在，先占位
```

3. 从工具仓复制 8 个输入文件（`<工具仓>` 换成你的 `ai-prompt-line` 实际路径）：

```powershell
Copy-Item <工具仓>\使用说明\资产\模板_*.md, <工具仓>\使用说明\资产\标准_产物质检清单.md, <工具仓>\使用说明\资产\工具_门禁检查器.py docs\模板\
```

4. **开工自检三件**：
   ① `git init` 已执行，且会话工作目录 = 项目根（AGENTS 才会自动加载）；
   ② `docs/模板/` 8 个文件齐：`模板_需求 / 模板_技术选型方案 / 模板_AGENTS项目规范 / 模板_验证阶段工作流 / 模板_选型验证报告 / 模板_学习记录 / 标准_产物质检清单 / 工具_门禁检查器`；
   ③ 之后所有输入一律读**项目内副本**，不回工具仓找、不靠聊天历史里的粘贴内容。

## S1 ·【R】整理需求（任意会话）

- **操作**：把下方整段复制到会话，替换 `{花括号}`；产出后**你确认**才转正（P0 只吃转正件）。
- **产出**：`docs/需求文档/{YYYY-MM-DD}_{项目名}需求.md`
- **验收**：四节齐、能力表 3–6 项且可验收、燃料事实带〔燃料：…〕、占位零残留（grep 实测）、事实缺口全进提案清单。

```text
当前工作目录就是新项目根。输入：
- 需求模板：读 `docs/模板/模板_需求.md`，严格按其结构产出
- 我的想法：{零散想法/背景/一句话目标——越乱越好，就是要你来整理}
  （示例：想做个图书馆管理系统，本地自己用，管图书、读者、借还书就行，最好能出报表——用 Java 和 SQLite 搞，别搞太复杂）
按模板结构产出**本项目真实需求文档**（1 目标【含能力表】/ 2 边界与性质 / 3 其它约束 / 4 提案与假设清单）：
1. 能力表：从我的想法提炼 3–6 项，**一行一能力、可验收**；你觉得缺了的补上并在提案清单标注；
2. 燃料事实必须显式化：影响后续验证阈值的具体数字与事实——目标规模（几实例/几类页面）、
   目标机器配置、运行时长/频率约束——写不出的标【需求待确认】；
   燃料事实在正文用〔燃料：…〕标注（可 grep 复核）；
   （需求里每多一个事实，下一步方案里就少一条【阈值待拍板】）
3. 提案纪律（禁止开放式提问）：只有我能定的事实（规模、机器、使用者、授权范围、不做的边界），
   写入模板第 4 节《提案与假设清单》：逐项给出建议默认值 + 理由 +【需求待确认】标记，等我确认；
   常识可推导的直接填默认并列入假设清单，不提问；
4. 只写"要什么"，不写"用什么技术"（技术选型是下一步 P0 的事）；
   输入里已含的技术选型一概不进正文，要留痕就写进第 4 节假设。
保存为 docs/需求文档/{YYYY-MM-DD}_{项目名}需求.md（目录不存在先创建）；生成后自查：四节齐（第 1 节含能力表）？能力表可验收？
燃料事实都带〔燃料：…〕标注了？grep `{花括号}|待填|TODO` 占位零残留（**实测，不看自称**）？
事实类缺口是否全部进提案清单？——逐项报告，等我确认后再定稿。
```

## S2 ·【P0】技术选型（任意会话，多轮）

- **操作**：确认需求转正后发下方整段；多轮打磨直到方案符合预期（可换模型互验）。
- **产出**：`docs/技术选型/{YYYY-MM-DD}_技术选型方案.md`
- **验收**：九节逐节在、验证路线每项三要素可测、否决清单齐、待拍板项集中 §9。

```text
- 方案模板：读 `docs/模板/模板_技术选型方案.md`（九节契约，按其结构逐节生成，不靠记忆）
- 原始需求为**已转正的需求文档**：{内容或路径——`docs/需求文档/{YYYY-MM-DD}_{项目名}需求.md`，已按 `模板_需求.md` 转正}
我要开发一个项目：{功能目标一段话，含平台/语言/关键约束}。上述需求文档为**封闭输入**：只消费、不改写、不回问，缺口走 §9 未决项。
输入卫生（核验门，不通过即停）：检查输入确为转正件——标题/文件名含"样例"、带免责头（"仅示范/勿照抄"类）、或落点不在 `docs/需求文档/`、命名不合规，任一命中即判样例/模板文件，退回转正后重发 P0；通过则直接进入九节生成。
按 `模板_技术选型方案.md` 的**九节结构契约**产出技术选型方案（文件头：日期/依据/状态/平台）：
1. 能力表；选型总体原则——必须含"复用优先、自研聚焦"：列出自研的 {2–3} 项，其余一律复用；
2. 按能力域给候选对比表（候选｜说明｜结论+理由），不许只给单一答案；单列"否决项汇总"：被否方案+一句理由；
3. 整体架构分层与模块划分：分层列表 + 模块表（模块｜职责一句话，命名按目标语言惯例：Python 用
   snake_case、禁止连字符）——这是后续 AGENTS 模块表的唯一来源；输入缺信息时标【待拍板】或按
   生态惯例填默认并记入 §9 未决项，禁止开放式提问；
4. 分阶段技术验证路线（方案心脏）：每项标准三要素齐全——指标+阈值+样本量/测量方法；
   阈值给依据，给不出标【阈值待拍板】，禁"较快/足够/稳定"等不可测词；
   "不通过的决策"列可选备选（A/B），不得写"再优化"；每项过标准四问：
   ①怎么测 ②测几次、怎么判 ③阈值哪来的 ④失败走哪条；
5. 依赖清单+版本约束+合规边界；{2-3} 个变体对比标推荐及综合利弊，留"未决项□清单"，等我拍板。
保存为 docs/技术选型/{YYYY-MM-DD}_技术选型方案.md（目录不存在先创建）；生成后按模板末尾"九节自查"逐节打勾。
```

## S3 · 你拍板（人工，S2 之后）

把方案发回会话，要求它：① 文件头状态改 **已拍板**；② 拍板结果写入 **§6 拍板结果表**；③ §9 未决项逐条关闭或转为假设。完成后你确认基线，才进 S4。

## S4 ·【P1】生成项目 AGENTS 与状态机（**目标项目根**新会话）

- **操作**：复制下方整段；这是唯一一次"生成 AGENTS"的机会。
- **产出**：`./AGENTS.md`（项目根，唯一输出文件）
- **验收**：占位零残留、§1.2 四件齐、§1.6 七字段与四查、§1.7 四问、§1.8 回路齐、判定条件与方案行项 1:1、方案内无越界看板。

```text
当前工作目录就是新项目根。请基于两份输入生成真实 AGENTS.md：
- 模板：读 `docs/模板/模板_AGENTS项目规范.md`（按其结构逐项替换，不靠记忆）
- 基线：{刚拍板的技术方案路径，重点是分阶段验证路线}
输出：保存为项目根 `./AGENTS.md`——这是唯一输出文件；状态机不是独立文件，无其它落点。
要求：
1. 逐项替换**一切占位形态**（`{花括号}`、`§X`、`{编号}` 等；名称/能力表/技术栈/否决清单/合规/模块表/量化标准），依据方案文档——其中 `§X` **必须解析为方案实号**（本项目验证路线=§7 这类）；生成后 grep 实测确认占位零残留，不看自称；
2. §1.2 状态机：用模板 §1.2 的骨架逐格生成——状态表 + 判定条件 checklist + 切换清单 + 激活分册指针；
   阶段划分与量化通过标准取自方案 §X 的分阶段验证表，判定条件与方案行项一一对应；
   状态表/✅⬜ 看板只写在 §1.2，严禁写入方案或任何其它文件（方案只在阶段结束时追加"验证结论"）；
   判定条件同步方案行项时，**【阈值待拍板】/□编号标记一并带入**；
3. §1.3 状态列初始化（未验证一律"待验证"）；§1.6 按结构化模板生成——任务状态表（任务ID/类型/目标/状态/验收判据/证据记录/更新日期）+ 挂起待拍板表 + 下一步 + 完整性四查；首次无任务时任务表只留表头或一条"待开始"的 V-01，下一步指向 V-01；§1.7 入口协议与 §1.8 规则反馈回路原样保留（强制门与纪律，不得删改或弱化）；
4. 标注【结构必留】的不得删，尤其：§1.2 状态机、§1.6 结构化状态表、§1.7 新会话入口协议、§1.8 规则反馈回路、§十汇报八段与状态同步必报、§1.5门禁、§2.4双写、§十一优先级；
5. 生成后自查并逐项报告：必改项速查表替换结果（见 `模板_AGENTS项目规范.md` **附录**；未提供该附录时，以模板各章节【必改】标注逐条自查并说明替代）+ §1.2 四件是否齐（状态表/判定条件/切换清单/指针）
   + §1.6 七字段与状态枚举是否齐、完整性四查是否在 + §1.7 四问是否齐 + §1.8 五步与状态四值是否齐
   + "判定条件 ↔ 方案行项"对应表 + 方案内有无越界看板；
6. 提案纪律（禁止开放式提问）：输入缺失信息时——凡可从方案 §8 生态推导的（代码目录布局、测试工具/
   linter/格式化、依赖管理工具），直接按生态惯例填默认值，不提问；
   只有用户能拍板的（发行名/品牌名），一次性提案 {3} 个候选 + 一句话理由等我确认；
7. 生成**假设清单**：列出你填了默认值的项与拿不准的点，等我确认后再保存到 ./AGENTS.md。
```

## S5 ·【P2】目录与验证分册（紧接 S4，同会话续发）

- **操作**：复制下方整段（分册模板已在 `docs/模板/`，读项目内副本）。
- **产出**：`docs/工作流/{分册名}.md` + 生成类目录 + `.gitignore`
- **验收**：分册名与 AGENTS §1.2 指针逐字一致、验证项清单七列齐全（含编号 V-NN）、逐项能对回方案 §X。

```text
当前工作目录就是新项目根。输入：
- 分册模板：读 `docs/模板/模板_验证阶段工作流.md`
- 基线：{已生成的 AGENTS.md 路径（取 §1.2 分册命名与指针）+ 技术选型方案路径}
按 AGENTS §2.2 创建生成类目录（docs/模板/ 已在建项时复制，不属本步）：需求文档/技术选型/架构设计/开发记录/验证记录/问题记录/技术决策/工作流/学习记录；
把分册模板生成为 docs/工作流/{分册名}.md——单期验证=验证阶段工作流.md，多阶段按 AGENTS §1.2
切换清单命名为 阶段N_阶段名工作流.md；替换方案文档名与阶段范围，【结构必留】章节不得删；
并读方案 §X 全部"分阶段验证路线"表，生成分册的"本阶段验证项清单"章节——按阶段分组，逐项给出：
编号（V-NN）｜验证项｜量化标准值｜出处（方案 §X 第 N 行）｜不通过预案｜本阶段产出物｜执行提示
（编号按阶段连续 V-01、V-02…，与 AGENTS §1.6 任务状态表的任务ID逐字一致；本项目上下文：脚本放 poc 哪个目录、样本量等）
标准值可入清单但必须标出处；
结论仍按 AGENTS §2.4 回写方案，清单不自行修改状态（状态只在 §1.2）；
生成 .gitignore（过滤 venv/__pycache__/缓存/日志/运行数据/打包产物/IDE，保留锁文件）；
完成后跑 git status 检查待提交清单并汇报。
```

## S6 ·【P3】验证任务循环（目标项目根会话，一次一项）

- **操作**：打开分册"本阶段验证项清单"，**一次取一项**：把该行"执行提示"填进 `{任务描述}`，编号填 `{任务ID}`；该项结论回写后再取下一项。**不要把整张清单一次性发。**
- **产出**：`docs/验证记录/`（含原始数据）+ 方案回写
- **验收**：先过入口协议；§十 八段汇报；"状态同步"逐项回答；§1.6 已回写且证据含六要素，缺原始数据不得置"已完成"。

```text
按 AGENTS.md 执行本任务：{任务描述}（任务ID：{V-01 / T-001}）
要求：
1. 若本会话是新会话，先按 §1.7 输出"续接四问"，我确认后再动手；非新会话也先报该任务在 §1.6 中的当前状态；
2. 按 §三分诊并列计划再动手；
3. 完成后严格按 §十 八段汇报，"状态同步"段必须逐项回答（含 §1.2 判定条件核对：尚缺哪几条）；
4. 收尾更新 §1.6：该任务ID的状态、证据/记录路径、更新日期，以及"下一步"；证据/记录须含六要素（环境/样本量口径/原始数据路径/实测值/阈值出处/判定），缺原始数据不得置"已完成"；完整性四查必须过；
5. 你发现规范缺口或收到我的纠偏时，按 §1.8 先记规则候选（L-NN，带证据路径与根因层），经我确认后才改规则；我对你的任何纠偏都会要求"把这条写进 AGENTS"。
```

## S7 ·【P4】选型验证报告（阶段或全部验证项跑完，你验收）

- **产出**：`docs/技术选型/{YYYY-MM-DD}_选型验证报告.md`
- **验收（收口判据，三条缺一不收口）**：① 证据表行数 = 分册验证项总数，每项有实测值与原始数据路径；② 判定只用 `通过/不通过/待补测/不适用`，按方案阈值比较；③ 报告经你确认"已验收"，且结论已回写方案 §7 与 AGENTS §1.6。

```text
按 AGENTS.md 生成选型验证报告：{阶段范围：如 阶段 0–1 全部验证项 / 全部验证项}（报告日期：{YYYY-MM-DD}）
输入：
- 报告模板：读 `docs/模板/模板_选型验证报告.md`
- 基线：{AGENTS.md 路径（取 §1.2 判定条件、§1.6 任务表与证据路径）+ 技术选型方案路径（取 §X 验证路线阈值）}
- 过程档案：docs/验证记录/ 目录下的全部验证记录

要求：
1. 若本会话是新会话，先按 §1.7 输出"续接四问"，我确认后再动手；非新会话也先报 §1.6 中相关任务的状态；
2. 先拉齐验证项全集：以激活分册"本阶段验证项清单"为准，逐项取 V-NN 编号与方案 §X 出处，不得漏项、不得自增项；
   若 AGENTS §1.6 与分册项数不一致：仍以分册为准出报告，差异逐条写入缺口清单，不擅自增删验证项；
3. 逐项找原始数据：到 docs/验证记录/ 对应记录中取环境、样本量、统计口径、原始数据路径、实测值；
   找不到原始数据的项，判定只能写"待补测"，**禁止**用对话印象或推算值补成"通过"；
4. 判定只用四值：通过 / 不通过 / 待补测 / 不适用；按方案阈值逐项比较，阈值逐字带出处、不得修改；
   不通过项写明启用哪个备选、谁拍板；未拍板的一项写入 §1.6 挂起表；
5. 总体结论三选一：可交付 / 走备选 / 未收口，并与判定计数自洽；
6. 按模板生成报告，保存为 docs/技术选型/{YYYY-MM-DD}_选型验证报告.md；状态先写"待验收"，等我确认后再改"已验收"；
7. 收口回写：方案 §X 每阶段表下追加"验证结论：{计数}（报告：{路径}）"；AGENTS §1.6 更新相关任务的状态/证据/日期；
   核对 §1.2 判定条件，全满足则宣告并执行切换清单，未满足写明尚缺哪几条；
8. 自查并按模板"生成后自查"逐项报告（实测点数，不看自称）：分册项数 = 证据表行数、每个通过有原始数据、阈值带出处、结论与计数自洽、回写已完成；
9. 输出缺口清单：待补测项、缺失证据、未拍板事项、环境不可复现项，各给下一步建议；报告状态未"已验收"前，结论不得当作基线。
```

## 收尾与续跑

- **新会话**：先让 AI 按 §1.7 输出"续接四问"（阶段与分册 / 任务与状态 / 挂起与拍板 / 一致性核对），你确认后再开工；再用一句话验收——"这个项目现在到哪一步、下一步干什么、按哪个流程？"。机制细节见 [`流程与机制.md`](流程与机制.md)。
- **排障**：见 [`常见问题.md`](常见问题.md)。

- **可选下游**：验证通过、方案确认可行后，继续用 S4–S6 进入正式开发；阶段收口或重大纠偏后加跑 S8；开工前与收尾各跑一次 S9 门禁。
