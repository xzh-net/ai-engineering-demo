# 使用说明 · 需求 → 选型 → 验证

> **这是使用者的唯一入口。** 修改者内容不在本目录。
> 本仓库的主线目的：把零散想法变成需求文档，完成技术选型，再通过验证确认方案可行。

---

## 0. 前置条件

1. **本仓库是工具箱，目标是另一个项目目录**：不要把模板/提示词复制进目标项目，造成双真源。
2. 新建目标项目根目录，并执行 `git init`。
3. 之后所有 AI 会话都以**目标项目根**为工作目录（这是 AGENTS 自动加载的唯一硬前提）。
4. 本仓库的 `prompts/` 与 `资产/` 是"来料"：在目标项目会话里必须**整份粘贴模板内容**，不能只给 `使用说明/资产/...` 路径（目标项目读不到本仓库文件）。

> **新会话入口协议（V0.2）**：每次新建会话或换窗口，AI 必须先输出"续接四问"——① 阶段与分册 ② 任务与状态 ③ 挂起与拍板 ④ 一致性核对；你确认后再开工。答不齐 → 回 P1 补 AGENTS §1.7 与 §1.6 结构化状态表。

> P1–P6 是**当前执行验证、复盘与门禁的载体**：没有 AGENTS 就没有状态与门禁，没有分册就没有逐项验证依据，没有 P4 报告就没有可验收的结论，没有 P5 复盘就没有规则沉淀，没有 P6 门禁就无法强制发现断链。它们同时也可用于验证通过后的正式开发。

> **R → P0 的转正规则**：R 产出后你先确认能力表、边界与燃料事实；确认后才算"转正件"，P0 只吃转正件。[`资产/样例_需求_工具箱.md`](资产/样例_需求_工具箱.md) 只做写法参照，不能当需求输入（P0 的输入卫生门会拒收）。

> **拍板动作（第 3 步）**：把方案发回会话，要求它：① 把文件头状态改为"已拍板"；② 把拍板结果写入 §6 拍板结果表；③ 未决项逐条关闭或转为假设。完成后你再确认基线。

> **P3 启动规则（第 6 步）**：打开分册"本阶段验证项清单"，**一次取一项**，把该行的"执行提示"填进 `{任务描述}`；该项结论回写后再取下一项。不要把整张清单一次性发。

> **收口判据（第 7 步 · V0.3 起以报告为准）**：① 报告证据表行数 = 分册验证项总数，每项有实测值与原始数据路径；② 判定只用 `通过/不通过/待补测/不适用` 四值，且按方案阈值比较；③ 报告状态经你确认后为"已验收"，且结论已回写方案 §7 与 AGENTS §1.6。三条缺一不收口；细节见 [`资产/模板_选型验证报告.md`](资产/模板_选型验证报告.md)。

> **复盘回路（第 8 步 · V0.4）**：阶段收口或发生重大纠偏后跑 P5——只把**已发生且有证据**的事件写进学习记录；每条候选（L-NN）先标"候选"，你确认后项目环写入 AGENTS §1.8、工具环由你人工回灌本仓；未在下一任务验证前不得说"已学会"。详见 [`资产/模板_学习记录.md`](资产/模板_学习记录.md)。

> **自动门禁（第 9 步 · V0.5）**：在目标项目根跑 `python <检查器路径> --root .`（检查器为 [`资产/工具_门禁检查器.py`](资产/工具_门禁检查器.py)，可直接用绝对路径调用），检查 AGENTS 结构、证据与项数、交叉引用、任务状态与断点四项；有不过项即退出码 1 并指出病层，检查器**只读、不自动改文件**。修完再跑，绿了按 §1.6"下一步"继续任务。编排话术见 [`prompts/P6_门禁.md`](prompts/P6_门禁.md)。

> **回归基准（V1.0）**：`python 资产/工具_门禁检查器.py --selftest` 对随附的 [`资产/样例_完整项目/`](资产/样例_完整项目/) 跑四项门禁，**期望四项全绿、退出码 0**；它是"工具仓自身没坏"的最小证据。改成"删一项证据"即可看到阻断与病层提示。

## 3. 送检

任一步产出物都可送检：把**产出物全文 + 工序名（R/P0/P1/P2/P4/P5/P6）+ 所用模板**发给任意 AI 会话，附 [`资产/标准_产物质检清单.md`](资产/标准_产物质检清单.md)，按其对应工序过检表逐项核。

- 输出三段式报告：过检清单 / 不过项 + 病层 / 修法建议。
- 根因在被检项目 → 按被检项目的 AGENTS 修。
- 根因在本仓库 → 交回本仓库维护者。
- **你手动送检是唯一触发器，不设强制。**

---

## 4. 机制是否生效：续接四问 + 三问验收

V0.2 起，新会话应先自报"续接四问"（见第 1 节）。你再用一句话验收：

> "这个项目现在到哪一步、下一步干什么、按哪个流程？"

四问答得齐、三问答得对 = 机制成立；答"我不知道/请补充" = 回去补 AGENTS §1.7 与 §1.6（见 [`流程与机制.md`](流程与机制.md) 的 §2.5）。

---

## 5. 可选下游

验证通过、方案确认可行后，继续用 P1–P3 进入正式开发；每个阶段或重大纠偏后加跑 P5，把复用经验固化为规则；开工前与收尾各跑一次 P6 门禁，防止状态与证据断链。此时同一套 AGENTS、分册、任务循环继续生效，不需要另起一套。
