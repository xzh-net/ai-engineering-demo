# 模板：需求文档（项目起点，P0 的输入）

> 用法：由手册 §5.2 的 **【R】提示词**驱动生成（推荐），或人工按本结构撰写；产出作为 P0 提示词"原始需求"输入槽的内容。写法颗粒度参照 `样例_需求_工具箱.md`。
> 与 `模板_技术选型方案.md` 的分工：需求 = **要什么**（能力与边界）；方案 = **用什么做、怎么验证**（选型与标准）。
> 标注：{花括号} 为占位；【必填】= P0 依赖它；〔燃料：…〕= 影响后续验证阈值的具体事实，正文保留此标注（与 `样例_需求_工具箱.md` 同形态）。

---

# {项目中文名}

## 1. 目标 【必填】

在 {平台/运行环境} 上{一句话说清要构建什么}，覆盖 {N} 项能力：

| 能力 | 说明 |
| --- | --- |
| {能力1} | {一句话：做什么、对象是什么} |
| {能力2} | {…} |
| {能力N} | {…} |

## 2. 边界与性质 【有则填】

- 项目性质：{测试与学习 / 个人工具 / 商用}；{离线/联网}。
- 明确不做：{如不绕过平台风控、不触碰他人账号——影响方案 §8 合规边界}。
- 受控对象与授权范围：{操作什么、谁授权}。

## 3. 其它约束 【有则填】

- {团队/人力、工期、目标机器配置等——影响方案 §9 未决项与验证阈值}。

## 4. 提案与假设清单 【有则填 · R 工序收尾必查】

> 只有用户能定的事实一次性提案、等确认；常识可推导的直接填默认、只列出不提问。

- 【需求待确认】：{逐条——规模 / 机器 / 使用者 / 授权范围 / 不做的边界；每条给"建议默认值 + 理由"}
- 假设：{已按默认值直接填入正文的推导项，列出即可}
- 用户确认结果：{确认后就地改标记并保留为决策留痕}

---

> 提示：需求写"要什么"，不要写"用什么技术"——技术选型是方案 §4 的事；
> 能力表会被 P0 提炼进方案 §1、被 P1 提炼进 AGENTS §1.1，务必**一行一能力、可验收**。
