# 审计清单（修改者专用）

> **不在使用者侧。** 使用者送检用 [`../使用说明/资产/标准_产物质检清单.md`](../使用说明/资产/标准_产物质检清单.md)；本文件只在**本仓库改完后回仓审计**时用。
> **修复归属**：根因在被检项目 → 按被检项目的 AGENTS 修；根因在本仓库的提示词/模板/质检 → 按 `项目介绍.md` 的修改三步修。**动手改文件一律经用户确认，审计会话只诊断开方。**

---

## 一、缺陷归因与病层定位（先三判据定性 → 再查病层）

### 第一步：归因三判据

| 判据 | 定性 → 去哪修 |
|---|---|
| 同一错误**跨 run / 跨项目复现** | **规格缺口**（提示词/模板/质检的准确定性）→ 修工具侧 |
| 错在"规则没写的地方"＝规格缺口；错在"规则写了的地方"且时对时错 | **模型不确定性** → 不堆提示词，改**验收实测化**（grep/点数、不看自称） |
| 发生在**流程跳步处 / 输入不合规处** | **流程执行**（人侧）→ 补流程条款或回头补做该工序 |

### 第二步：病层定位表（症状 → 病在哪层 → 只改那层）

| 症状 | 病层 | 修法 |
|---|---|---|
| 产出缺结构/少章节 | 模板契约缺节，或提示词没引用模板 | 补模板节，或提示词加"按 XX 模板生成" |
| AI 反问模板在哪 / 自编结构 | 提示词缺**文件名+输入槽** | 补输入槽 |
| 同一产物两处都在生成（分册/目录/gitignore 类） | 流程分工 | 收敛**唯一责任人**，另一处改引用 |
| 硬编码章节号（§六）、实例名、连字符模块名 | 泛化/命名纪律缺失 | 改对应模板或提示词条文 |
| 占位残留（§X / {花括号} / 待填） | 提示词自查未实测化 | 自查条款加"grep 实测" |
| 自称通过但实测不过 | 同上；一切以文件实际内容为准 | 同上 + 复核历史 [x] 勾选 |
| 同一标准多处出现且不一致 | 违反"唯一落点" | 归位到 §1.2 / 方案单点，其余改概述 |
| 两份文件说法打架 | 双真源 | 收敛单一真源，另一处改指针 |
| 判据把模板授权的内容判违规 | 质检标准措辞（判据过宽） | 收紧限定词 + 回查该判据此前的判定是否误伤 |

## 二、修后交叉引用审计（grep 必查，改完必跑）

> **适用范围**：#1/#2/#3/#5 随产出物流动，被检项目现场也能跑；#4/#6 需对照本仓库的产物落点表与文件地图，**仅在本仓库回仓审计时跑**。

```text
1 旧文件名 / 旧章节指称     ：把正文中每个 `*.md/*.py/*.drawio` 文件名与 git ls-files 实体名逐个比对，同名才算过
                              （`维护/修改记录.md` 的历史条目按当时文件名记录，不作为现存实体校验；其余文件零残留）
2 硬编码章节号              ：方案 §六 | §X\.X          （模板类文件应为 §X）
3 占位残留                  ：§X | \{[^}]+\} | 待填 | TODO   （逐处核是否为合法示例；提示词/模板里的示例占位为有意保留）
4 双责任人                  ：对照 `使用说明/README.md` 的产物落点表 + `项目介绍.md` 的文件地图，任一产物唯一 owner
5 配套互指                  ：每文件头部"配套"列的文件都存在；使用者侧每个文件都被至少一份配套列出
                              （`维护/修改记录.md` 只属维护侧，不计入使用者侧清单）
6 计数与序号                ：常见问题条目连续、附录/过检表行数自洽
```

**通过标准：适用范围内的各条 grep 全部零异常（仓内回仓审计跑 #1–#6；被检项目现场跑 #1/#2/#3/#5）；例外仅限有意保留的示例外联与提示词占位。**

**工具仓回归（V1.0 起必跑）**：`python 使用说明/资产/工具_门禁检查器.py --selftest`，对黄金样例跑四项门禁，**退出码必须为 0**；不为 0 说明样例或检查器本身已坏，先修工具仓再谈被检项目。
