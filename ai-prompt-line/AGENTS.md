> **手工维护声明**：本文件不经本仓库的 R/P0–P3 管线生成、**不设状态机、不设门禁、不设"状态同步"必报项**——本仓库自己不接自更新机制（防鸡生蛋）。以项目根为工作目录开新会话即自动加载。
> **读者声明**：本文件面向**修改者**。使用者请从 [`README.md`](README.md) 进入 [`使用说明/`](使用说明/)；修改者请先读 [`维护/项目介绍.md`](维护/项目介绍.md)，再读 [`维护/修改记录.md`](维护/修改记录.md)。

## 一、项目定位

**ai-prompt-line** 是一条"从零散想法到可验证技术选型"的**提示词生产线**：主线是 **需求 → 技术选型 → 验证执行 → 选型结论**；P1–P6（AGENTS/分册/任务循环/验证报告/学习回路/门禁编排）是执行验证、复盘、门禁与后续开发的载体，不是目的本身。

本仓库性质：**文档 + 提示词 + 只读检查器 + 黄金样例的工具仓，无运行时服务**。版本路线：V0.1 可读 → V0.2 可续 → V0.3 可证 → V0.4 可学 → V0.5 自动 → **V1.0 可交付（已完成：黄金样例 + 回归基准）**。首个方法论自举对象是它自己（本仓库自身的 `AGENTS.md` 手工维护、不经管线生成）。

**三个认知（新会话防错）**：

1. 本仓库**生产**别的项目的 AGENTS——但**自己的 AGENTS 例外**（手工维护）；**禁止**用 R/P0–P3 改写本仓库文件。
2. 双层结构：**规格层**（提示词/模板/质检，定义"什么算对"）/ **执行层**（状态/门禁/证据/学习/编排，V0.2 起）——改内容先问"这属于哪一层"。
3. **两个身份严格分开**：使用者侧（`README.md` + `使用说明/`）只写能改变使用者下一步动作的内容；修改者侧（`维护/` + 本文件）才写设计理由、改名过程、旧结论推翻关系、维护纪律。两边的文件不互相引用正文，只做入口指引。

## 三、修改纪律（问题处理方式 · 自我修复 playbook）

1. **分层修复**：病在提示词/模板/使用说明/质检哪一层，只改那一层（病层定位表见 `维护/审计清单.md`）——跨层连改是事故之源。
2. **经确认执行**：任何文件改动先向用户说明（改哪、为什么、影响哪些引用），确认后动手；无自动回写。
   **动手前先读 `维护/修改记录.md`**（末 3 条 + 与本次改动相关的条目）——了解被推翻的旧结论、既往影响面与既有归档格式，避免重犯与重复记录。
3. **修改三步**：① 改一处 → ② **交叉引用审计**（跑 `维护/审计清单.md` 的六条 grep + 工具仓回归 `--selftest`，零异常才算完）→ ③ 按性质归档：**给使用者的指导**写进 `使用说明/`（常见问题或机制章节），**过程与时间**（改了哪、何时改、为何改、影响哪些引用、旧结论被谁推翻）写进 `维护/修改记录.md`——使用说明里不写实录。
4. **泛化三不**：不硬编码章节号（用 §X，不用 §六）、不硬编码实例名（用 {分册名}）、不给同一产物留第二责任人。
5. **规则住模板、提示词只管动作与纪律**：能沉进模板结构的规则不写进提示词（防两处漂移）。

## 四、送检与修复流程（产出物审计）

- 用户送检（产出物全文 + 工序名 + 所用模板）→ 会话按 `使用说明/资产/标准_产物质检清单.md` 对应工序（R/P0/P1/P2/P4/P5/P6）**过检表**逐项核 → 输出三段式报告（过检 / 不过项+病层 / 修法建议）→ **根因在被检项目**按其 AGENTS 修；**根因在本仓库**按本文件 §三修 → 修后跑 `维护/审计清单.md` 的 grep → 按 §三.3 分别归档（指导入使用说明、过程入修改记录）。
- 触发者永远是用户手动送检；**本仓库不设任何强制送检/必报机制**。

## 五、交付汇报（精简七段，去必报）

向用户汇报修改/审计时给出：本次任务 / 修改文件 / 实现内容 / 审计结果（含 grep 六条结论）/ 记录位置（使用说明条目 + `维护/修改记录.md` 条目）/ 遗留问题 / 下一步建议。

**不设"状态同步"必报项**——本仓库无状态机，无状态可同步。

## 六、最高优先级

1. 用户明确指令与手动评审 > 本文件纪律 > AI 推测。
2. 不给本仓库引入自更新机制（状态机/门禁/必报/自动回写）——这是硬边界，任何会话不得以"完善机制"为由添加。
3. 与其它项目的关系：本文件**不由**本仓库模板生成，模板的适用对象是外部项目；两者结构相似是刻意为之（吃自己的狗粮），但生成关系不存在。
4. 未经验证的修改不声称完成；指导与修改记录未分别归档不算收尾。
