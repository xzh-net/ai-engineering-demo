# ai-prompt-line

> 喂它一个想法，它输出一整套可执行的项目规范——一条从零散想法到 AI 可执行项目的**提示词生产线**。

管线：**想法 →【R】需求 →【P0】技术方案 → 你拍板 →【P1】AGENTS+状态机 →【P2】分册 →【P3】任务循环**

| 文件 | 角色 |
|---|---|
| `AI编程指南_新项目快速生成AGENTS与状态机.md` | 主文档：机制、用法、提示词原文、常用指导（活章节） |
| `模板_需求.md` + `样例_需求_工具箱.md` | R 工序：需求结构 + 写法样例 |
| `模板_技术选型方案.md` | P0 工序：九节结构契约 |
| `模板_AGENTS项目规范.md` | P1 工序：AGENTS 规范（状态机骨架 + 必改速查表附录） |
| `模板_验证阶段工作流.md` | P2 工序：验证分册模板 |
| `AGENTS.md` | 本仓库治理：文件地图、修改纪律、送检修复流程（**手工维护，无自更新机制**） |
| `标准_产物质检清单.md` | 质检标准：R/P0/P1/P2 四工序过检表 + 病层定位 + 修后审计 grep（整份可粘贴送检） |
| `修改记录.md` | **修改者专用**：改动过程、旧结论推翻关系、条目格式——使用者不需要读 |

**快速通道**：① 复制 `模板_AGENTS项目规范.md` 到新项目根作 `AGENTS.md`，`git init` ② 在项目根开新会话，按主文档 §5.2 依次发【R】→【P0】→（拍板）→【P1】→【P2】 ③ 首次 commit 后用【P3】跑任务循环——汇报必报"状态同步"，踩坑按 §六三行格式回填主文档（只写可操作指导）。

**送检**：任一步产出物可按 `标准_产物质检清单.md` 送检——贴产出物+工序名+所用模板给任意 AI 会话，按清单过检、定位病层、经你确认后修复。

> 第一套用这条生产线的方法论反复打磨出来的文档就是它自己（自举）；本仓库自身的 `AGENTS.md` 为手工维护、不经本管线生成。
