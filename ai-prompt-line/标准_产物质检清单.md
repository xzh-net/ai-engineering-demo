# QC · 产物质检清单（送检用，随产物流动）

> **用法（送检姿势）**：把**产出物全文 + 工序名（R / P0 / P1 / P2）+ 所用模板**（内容或文件名）发给任意 AI 会话，让它按本清单逐项过检，输出**三段式报告：过检清单（打勾表）/ 不过项（行号 + 病层）/ 修法建议（指到哪一层改）**。
> **定位**：本文件是**质检标准（帮助文档）**，不是 AGENTS 规则——送检会话的工作目录在**被检项目**里，ai-prompt-line 的 AGENTS 不会自动加载，所以标准必须整份可粘贴、随产出物流动。
> **修复归属**：根因在被检项目 → 按被检项目的 AGENTS 修；根因在 ai-prompt-line 的提示词/模板 → 回 ai-prompt-line 按其 `AGENTS.md` §三纪律修（经用户确认）。**动手改文件一律经用户确认，审计会话只诊断开方。**

## 五、缺陷归因与病层定位（先三判据定性 → 再查病层）

**第一步：归因三判据**

| 判据 | 定性 → 去哪修 |
|---|---|
| 同一错误**跨 run / 跨项目复现** | **规格缺口**（提示词/模板/QC 的准确定性）→ 修工具侧 |
| 错在"规则没写的地方"＝规格缺口；错在"规则写了的地方"且时对时错＝ | **模型不确定性** → 不堆提示词，改**验收实测化**（grep/点数、不看自称） |
| 发生在**流程跳步处 / 输入不合规处** | **流程执行**（人侧）→ 补流程条款或回头补做该工序 |

**第二步：病层定位表（症状 → 病在哪层 → 只改那层）**

| 症状 | 病层 | 修法 |
|---|---|---|
| 产出缺结构/少章节 | 模板契约缺节，或提示词没引用模板 | 补模板节，或提示词加"按 XX 模板生成" |
| AI 反问模板在哪 / 自编结构 | 提示词缺**文件名+输入槽** | 补输入槽 |
| 同一产物两处都在生成（分册/目录/gitignore 类） | 流程分工 | 收敛**唯一责任人**，另一处改引用 |
| 硬编码章节号（§六）、实例名、连字符模块名 | 泛化/命名纪律缺失 | 改对应模板或提示词条文 |
| 占位残留（§X / {花括号} / 待填） | 提示词自查未实测化 | 自查条款加"grep 实测" |
| 自称通过但实测不过 | 同上；一切以文件实际内容为准 | 同上 + 复核历史 [x] 勾选 |
| 同一标准多处出现且不一致 | 违反"唯一落点" | 归位到 §1.2 / 方案单点，其余改概述 |
| 两份文件说法打架 | 双真源 | 收敛单一真源，另一处改指针 |
| 判据把模板授权的内容判违规 | 质检标准措辞（判据过宽） | 收紧限定词 + 回查该判据此前的判定是否误伤 |
